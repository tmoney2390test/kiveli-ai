# Subscriber chat paths

Kivelle+ and Max subscribers can start an alternate path from the newest completed reply in a direct chat. The action creates a separate Life, switches to it, and opens a new direct conversation. The original Life, transcript, and relationships remain unchanged. The branch appears in **Your Lives** and can be reopened there or from its original chat. The branch chat offers **Return to original**.

This first release deliberately does not rewind an earlier turn or branch a branch or group chat. A branch cannot start while a reply, active scene, upcoming plan, Date, or trip with that companion is in progress. Those conditions need a completed, stable state before copying. Previously completed plans, Dates, Moments, media, and life events remain in the original Life; saved memories, relationships, character state, story progress, world familiarity, and the conversation summary are copied. The branch has a text-only immutable snapshot of up to the last 150 visible source messages. Media stays in its original chat. The copied transcript cannot be edited, favorited, or charged again.

The server checks the current subscription, active Life, source ownership, latest assistant anchor, active-conversation limit, and idempotency request ID inside one database transaction. The two branch tables and the creation function are service-role only. Branch and source content remain owner scoped in the conversation API; new dialogue uses the selected Life and copied character instance. Branch Lives do not consume the purchased count of separately authored Lives, but their active conversations consume normal chat slots. An account may keep up to 20 paths on Kivelle+ or 50 on Max; deleting a branch Life frees its path slot. An active-memory budget also prevents an unbounded clone.

Deploy the additive migration before deploying the updated Edge Functions and client. Roll back the application to hide creation while preserving branch tables and existing paths. Do not drop the tables or narrow the continuity-kind constraint while branch Lives exist. Database tests require a running local Supabase Postgres instance (`supabase start`, then `supabase test db`). Validate a subscriber's branch creation, continuation, return to original, and Life deletion in staging before release.
